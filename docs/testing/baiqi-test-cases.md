# 白绮【为我前驱】测试用例

版本：2026-10-31。执行前阅读[验收方案](baiqi-acceptance-plan.md)，按[需求表](../requirements/baiqi-requirements.md)追踪。

**40 项用例初始状态全部为 NOT_RUN。** 当前结果另见[首轮运行记录](results/2026-10-31-p1-smoke.md)。下文 F01～F08 是夹具设计，不表示完整夹具均已生成。每次执行使用独立副本，记录实际构建、配置、前态、步骤、后态与证据；不能把本文预期复制成实际结果。凡引用尚未冻结的参数或未具备的测试钩子，执行时记 BLOCKED。每项证据均需含配置／存档指纹与运行号，以下只列额外重点。

## 身份、接管与生产

<a id="tc-001"></a>
### TC-001 领袖加载与实际生效

- 需求：BR-001。夹具：F01，安装待测构建并清楚记录所需规则集与 DLC。
- 步骤：进入选人界面，选择白绮；启动新局，检查能力说明和托管入口；查看数据库／脚本加载诊断。
- 预期：显示【白绮】【为我前驱】，没有裸露本地化键或缺项；进入游戏的玩家确为该领袖；能力挂接有效，没有相关数据库或 Lua 加载错误。
- 证据：选人及局内截图、玩家／领袖读回、加载日志。仅看到文字不证明能力生效，后续行为用例仍需运行。

<a id="tc-002"></a>
### TC-002 非白绮与他人对象隔离

- 需求：BR-003。夹具：F01／F04，白绮局含其他玩家对象，另有非白绮本地玩家对照局。
- 步骤：分别推进至规划时点；对白绮局记录己方与他人生产、文职任务；对照局留空队列并观察。
- 预期：只有当前白绮玩家的合格对象被托管；非白绮局不启用该能力，其他玩家对象无本模组写入。不能将其他文明自身 AI 行为算作本模组越权或成功。
- 证据：玩家／所有者标识、动作来源与前后队列，记录实际控制目标，不只统计请求总数。

<a id="tc-003"></a>
### TC-003 默认自动与低操作入口

- 需求：BR-002。夹具：F01，白绮新局和至少两座有合法任务的城市。
- 步骤：不逐城开启托管，推进到规划时点；查看总开关与城市／文职接管入口；正常结束回合。
- 预期：默认开始合法内政，不要求反复确认生产／选址；总开关和局部接管可找到，不需设置多套逐城参数。科技等范围外提示另行记数。
- 证据：录屏或交互清单、触发时机、实际队列和对象状态。

<a id="tc-004"></a>
### TC-004 总开关、局部接管与明确恢复

- 需求：BR-004。夹具：F01／F03，城市与未编队文职单位均有可执行任务。
- 步骤：分别关闭总开关、接管一城、手动移动一个文职单位；跨规划时点观察；恢复总开关但不交回局部对象；最后明确交回。
- 预期：关闭后无新的后台请求；局部接管不影响其他合格对象；玩家文职操作后暂停其任务，不能被下一轮覆盖。总开关恢复不自动解除局部暂停；明确交回后按现状重规划。已被引擎接受的旧请求单列核实。
- 证据：开关／接管状态、时间顺序、请求来源、手动操作前后状态。

<a id="tc-005"></a>
### TC-005 手动生产队列优先

- 需求：BR-004。夹具：F01，两个不同且合法的手动生产项，记录其顺序与进度。
- 步骤：玩家设定队列，开启托管并推进；生产中再手动更换第一项；待手动队列自然完成，观察空队列接续。
- 预期：托管不改写、清空、重排或反复争抢手动项，不损坏已有进度；手动内容结束后才补任务，局部暂停时仍不补。
- 证据：每个规划点的队列／进度快照和写入来源，原版界面的实际读回。

<a id="tc-006"></a>
### TC-006 建筑正常生产、完成与接续

- 需求：BR-005、BR-008。夹具：F01，有前置、产能和至少两个合法建筑／项目；核算当前速度和修正后的成本。
- 步骤：留空队列让托管选择；逐回合记录投入与剩余；等待首项真实完成，再观察下一项。项目与建筑分别选可验证样本。
- 预期：实际队列与合法选择一致，按正常产能和溢出规则推进；完成后建筑列表／项目结果真实变化，再接续。请求成功或队列入项不算建成，无免费生成与隐形扣费。
- 证据：成本来源、逐回合产能／进度、完成前后建筑或项目状态、余额与资源变化。

<a id="tc-007"></a>
### TC-007 军队补充有界且等待指挥

- 需求：BR-006、BR-015。夹具：F01／F04，有缺兵、达到需求上限、资源不足和财政低于储备的独立副本。
- 步骤：各副本触发规划；对允许训练者等到完成，跨一个完整规划周期；对达到上限者持续观察后续生产。
- 预期：只在需求和预算允许时补兵，正常支付产能／资源并计入维护费；不足时安排其他合法项或等待，达到上限不继续无穷招募。新兵没有后台移动／作战命令，军事待命提示允许存在。
- 证据：需求／预算计算、入队时状态、完成后资源与维护费、单位命令来源。

## 区域、改良与合法性

<a id="tc-008"></a>
### TC-008 普通区域自动选址并建成

- 需求：BR-007。夹具：F02，有至少两个已探明合法候选及一个不合法候选，人口与前置满足。
- 步骤：不手动放区域；触发规划，记录选择坐标；等待正常区域生产完成。
- 预期：合法候选被自动选中，请求包含实际目标而非只切入放置模式；在该地点真实建成，正常消耗产能，无玩家补点选址。
- 证据：候选及合法性依据、坐标、队列进度、完成地块／区域状态。只出现规划标记不算通过。

<a id="tc-009"></a>
### TC-009 前置、容量与特有区域

- 需求：BR-007、BR-008。夹具：F02，分别缺科技／市政、区域容量已满、无合法地块；所选文明有特有区域时加相应副本。
- 步骤：每个副本先触发规划；仅改变缺失条件后再次规划。对支持的特有区域跑完正常建设。
- 预期：条件不足时不提交非法请求、不绕过人口容量；恢复合法后能够规划。实际区域类型符合文明替代关系。无特有区域的文明可将该子项标明不适用，不能省略普通区域与容量测试。
- 证据：前置／人口／地形读回、请求与跳过原因、类型和完成状态。

<a id="tc-010"></a>
### TC-010 保留地块与受保护资产

- 需求：BR-007。夹具：F02，玩家明确保留地块及配置保护的资源／设施，另有可用候选。
- 步骤：触发区域与改良规划；让可用候选随后失效，再规划；解除一个保留后重试。
- 预期：不覆盖明确保留项或未获准移除的资产；无合适地点时等待，不为完成目标强行占用；解除保留后再按规则考虑该地。保护政策与引擎合法性分别记录。
- 证据：保护配置、候选过滤原因、地块前后资产状态。

<a id="tc-011"></a>
### TC-011 建造者移动与次数消耗

- 需求：BR-008、BR-009。夹具：F02，未编队建造者、已探明路线与合法改良，固定初始次数／行动力。
- 步骤：不手动命令，观察建造者走到目标并改良；再观察剩余次数不足或用尽时处理。
- 预期：移动和改良合法，实际地块产出／设施变化，次数与单位消失时机符合当前规则；不会复制建造者、无成本刷改良或改为军事动作。
- 证据：每步位置、行动力／次数、设施与收益前后状态、动作来源及原版规则基线。

<a id="tc-012"></a>
### TC-012 受损改良、区域与建筑修复

- 需求：BR-008、BR-009。夹具：F02，三类真实受损资产；先用原版操作确认各自合法修复方式和成本。
- 步骤：分别让托管安排建造者修复改良、城市队列修复区域／建筑；等实际修复完成。
- 预期：使用正确对象和正常规则；修复是否消耗建造者次数以实际基线为准，不统一假设扣一次；产能项目不免费瞬完。修复后损坏状态和相应收益恢复，无重复补偿。
- 证据：对照基线、损坏状态、修复请求、进度／次数／收益变化。

<a id="tc-013"></a>
### TC-013 无合法任务的有限等待

- 需求：BR-005、BR-026。夹具：F01／F02，所有候选暂时非法或受保护，另备可用的正常后备项目。
- 步骤：跨多个规划点观察；分别测试存在合法后备项和完全无合法项；之后开放一个候选。
- 预期：前者按策略用后备项，后者有界等待；不反复清队列、无限请求或弹窗。触发条件改变后恢复，不能永久死锁。
- 证据：每轮候选／请求／重试数与冻结上限、原因提示次数、条件改变后的真实队列。

## 和平扩张与控制边界

<a id="tc-014"></a>
### TC-014 开局移民自动建立首都

- 需求：BR-010、BR-025。夹具：F03，开局移民未编队，已探明范围存在合法地点，无需移除受保护资产。
- 步骤：不下移民或建城命令；推进必要回合，观察候选、移动、到达重检与建城；随后观察首个合法生产时点。
- 预期：自动完成真实建城，消耗该移民；城市位置合法、属于白绮并接入内政。无需玩家先手动建立首都，也不借用军队探路。
- 证据：初始状态、可见候选和路线、建城前后移民与城市、初次生产状态。

<a id="tc-015"></a>
### TC-015 正常生产后续移民的完整扩张

- 需求：BR-008、BR-010、BR-015、BR-025。夹具：F03，已有城市、无额外预置移民，人口／产能／预算允许，存在安全合法城址。
- 步骤：从托管决定训练开始，记录完整正常生产；核对完成时人口成本；观察移民移动、到达重检、建城和新城生产。
- 预期：移民从真实生产获得，人口及成本按规则发生在正确阶段；建城不再重复扣训练人口，原城保持策略要求余量；新城真实存在并接管。测试中不能用赠送或快完成移民替代该流程。
- 证据：生产起点至完成的成本／人口／队列、路线和单位消耗、新城所有权及队列。

<a id="tc-016"></a>
### TC-016 可见性、危险、边界与到达重检

- 需求：BR-011、BR-026。夹具：F03，分别有未探明诱人地点、可见敌军、封闭边界、不可达路线；另有出发后被占用的原合法地点。
- 步骤：逐副本规划；对在途移民改变目标合法性或可见威胁，再推进到下一步；查看等待与重规划。
- 预期：不使用隐藏信息，不越过规则限制；危险或失效时延后／换合法路线，到达后重新检验而非沿旧计划强行建城。后台不宣战、不指挥军队清路；理由提示有界。
- 证据：当时可见性／边境／威胁、候选与路径依据、到达检查、请求来源。未知敌情导致损失需按可见信息分析，不能简单判“必须零损失”。

<a id="tc-017"></a>
### TC-017 多城移民与城址预留

- 需求：BR-012、BR-015。夹具：F03，多城同时能出移民，已有一名在途移民，安全城址有限。
- 步骤：同轮触发所有城市规划；观察在建、在途和预留；取消一项或使其失效后再规划。
- 预期：同一城址／扩张任务只占一个名额；计入已有与在建移民，不同时无限追加；过期预留释放，剩余合法目标能继续使用。
- 证据：真实单位／队列与预留表对照、创建／释放原因、扩张预算与人口变化。

<a id="tc-018"></a>
### TC-018 对象转手、被俘、保留与夷平

- 需求：BR-003、BR-024、BR-025。夹具：F04，有在途任务；分别准备单位被俘／失去、己城转手、玩家攻城选择保留或依法可夷平的存档。
- 步骤：让状态变化发生，再触发规划；对保留城市观察首个合法内政时点；对失去或夷平对象读档后再规划。
- 预期：旧所有者任务失效，不控制他人单位／城市，不访问已删除对象；保留城市接管并合法恢复，夷平城市不重建或继续扣费。原版不允许夷平的对象不能强行测试夷平。
- 证据：前后所有者和对象映射、任务清理、保留城队列与错误日志。

<a id="tc-019"></a>
### TC-019 军事与非白名单单位隔离

- 需求：BR-006、BR-013、BR-014。夹具：F04，涵盖陆军／斥候／支援／海空军、军团／集团军与非白名单文职；另观察新招募军队。
- 步骤：让各单位处于可行动状态，后台运行一轮受控窗口；玩家随后分别发出合法军事命令。
- 预期：后台对这些对象无命令，所有军事动作保持玩家可用；玩家命令正常执行。军团形态不被误当成文职护送检查；非白名单单位不因“无战斗力”就被接管。
- 证据：入口白名单审查、各单位类型／所有者、动作来源与受控前后状态；未能准备的类型记阻塞并限定覆盖，不能一概通过。

<a id="tc-020"></a>
### TC-020 护送编队不发生间接军事移动

- 需求：BR-013、BR-014。夹具：F04，移民／建造者分别与军队形成护送编队，另备未编队对照。
- 步骤：为文职提供可执行任务，运行后台；再由玩家移动编队；测试无法读出编队状态的受控故障分支。
- 预期：后台跳过编队文职，护卫不被间接移动，也不自动解散编队；未知编队状态保持不动。玩家移动仍有效；未编队对照可正常托管。`GetFormationUnitCount()` 与 `GetMilitaryFormation()` 含义不能混用。
- 证据：编队状态、源自后台的文职请求为零、受控窗口两单位位置／行动／订单、故障诊断。

<a id="tc-021"></a>
### TC-021 玩家既有命令与自然回合变化

- 需求：BR-014。夹具：F04，军队有玩家预先指定的多回合路径，另一军队保持待命，另有可控回合刷新／敌方动作。
- 步骤：记录玩家原命令；托管开／关副本各跨回合观察；玩家主动攻击或休息后再次规划。
- 预期：后台不改变原目标、命令或军事状态；允许引擎继续玩家路径、刷新行动力或执行敌方攻击。玩家新命令也不被托管覆盖，不能将任何坐标变化都误报为越权。
- 证据：命令来源与时间线、匹配对照、引擎事件、受控变化原因及无法归因项。

<a id="tc-022"></a>
### TC-022 托管与文职任务保存恢复

- 需求：BR-004、BR-024。夹具：F03／F04，有手动城市、手动文职、在途移民和有效预留。
- 步骤：分别在总开关开／关时保存退出并读档；跨规划点观察；再明确交回暂停对象。
- 预期：总开关、局部暂停与手动队列保持；恢复前核对单位／城址现状，无重复任务或旧移动重放；有效任务可继续，交回后才重新接管手动对象。
- 证据：保存前后开关／队列／任务、单位实际状态、恢复检查和请求记录。

## 玩家主动有偿夺取

<a id="tc-023"></a>
### TC-023 资格展示、报价与取消

- 需求：BR-016、BR-017、BR-021。夹具：F05，资格条件与费用配置已冻结，每项条件分别不满足的副本。
- 步骤：选军队／目标查看动作，逐项检查不满足原因；合格副本查看报价后取消，不确认；跨下一规划点再观察。
- 预期：只对支持对象提供符合配置的入口，显示实际条件、币种与代价；取消不发夺取请求、不扣钱或行动、不启动冷却。UI 是否隐藏或禁用可以按实现决定，但原因可查。
- 证据：资格与报价读回、界面、取消前后余额／行动／所有权／冷却、请求数。

<a id="tc-024"></a>
### TC-024 代价与资格阈值边界

- 需求：BR-017、BR-020。夹具：F05，除了待测项外其他资格相同；每次从新副本开始。
- 步骤：金币草案分别设余额 `C-1`、`C`、`C+1` 并确认；分别测试配置采用的生命阈值 `H±1`／边界、距离 `R`／边界、行动不足和冷却到期边界。记录阈值是否包含等号。
- 预期：不足时明确拒绝且无扣费；恰好足够时能按规则完成，余额与行动／冷却恰好结算一次；超出余额保留差额。资格边界与冻结比较运算一致，不用草案里未采用的条件判错。
- 证据：费用函数输入／输出、独立副本指纹、前后余额与行动、目标及条件读回。

<a id="tc-025"></a>
### TC-025 普通主要文明城市真实夺取

- 需求：BR-018、BR-020、BR-023、BR-025。夹具：F05，合格的敌方主要文明普通城市及已清点资产。
- 步骤：玩家选择军队并确认一次；等待真实结果，查看双方控制和城市清单；推进到首个合法生产点。
- 预期：原地点的原城市真实转由白绮控制，旧控制者失去控制，不以赠送城邦或销毁再造冒充；费用／行动结算一次，资产按配置处理；城市接入托管，未指定军队不受指挥。
- 证据：前后所有权、城市位置和标识映射、建筑／区域清单、费用与行动、实际操作城市与生产队列。

<a id="tc-026"></a>
### TC-026 确认前目标、行动者与费用变化

- 需求：BR-017、BR-021。夹具：F05，打开报价后可分别改变余额、目标所有者、距离／资格、单位存在／所有者和影响费用的状态。
- 步骤：每个独立副本只改变一项，之后确认旧报价；包括单位被移走、失去行动、目标被第三方拿走和费用上涨。
- 预期：提交前重新检查；失效时不执行、不扣费；报价变化须展示新代价并重新确认，不能静默多扣。目标变化不能转而夺取另一个目标，过期单位任务被清理。
- 证据：旧新报价及输入、变更时间线、最终请求与所有者／余额／行动状态。

<a id="tc-027"></a>
### TC-027 双击、重复回执与次数限制

- 需求：BR-020。夹具：F05／F07，合格请求与实现可用的重复输入／回执注入能力。
- 步骤：快速重复确认；对同一请求投递重复结果；完成后同回合重试受次数／冷却限制的动作。每种路径单独副本。
- 预期：重复输入被归并或拒绝，一次实际结果只计一次费用／行动／次数，不重复转移或重复获利；真正新的请求仍按新资格检查。不能只靠暂时禁按钮证明结算可防重。
- 证据：原始输入／请求关联号、真实转移次数、结算记录与独立余额、冷却／次数读回。

<a id="tc-028"></a>
### TC-028 明确失败与补偿不重复

- 需求：BR-021。夹具：F07，可重复制造引擎明确拒绝或已证实未执行，不使用“等待超时”替代明确失败。
- 步骤：分别在未扣费路径与实现存在的预扣路径触发失败；重复投递相同失败通知并读档。
- 预期：未执行不收费、不耗行动或冷却；有预扣则确定失败后一次补偿，重复通知／读档不重复退款。补偿方式若有其他成本也需精确还原，不产生额外收益。
- 证据：明确失败证据、扣款／补偿关联、独立余额和行动前后、重复事件记录。

<a id="tc-029"></a>
### TC-029 结果未知时冻结与因果对账

- 需求：BR-022、BR-026。夹具：F07，能中断结果通知或使读取暂不可用；另备第三方在此窗口夺城的副本。
- 步骤：请求后阻断足够证据，跨规划点并尝试再次操作；恢复读取后分别观察实际成功、实际未执行、仅第三方导致归属变化的情况。
- 预期：未确定期间冻结冲突操作，不盲重发、退款或先发奖励；仅在实际状态与原请求因果得到证实后按唯一结果结算。第三方转移不算本次成功，证据仍不足则继续明确阻塞。
- 证据：被阻断内容、请求关联、时间线、不同来源的归属变化、对账依据与期间费用／请求数。

<a id="tc-030"></a>
### TC-030 夺取真实阶段的保存与恢复

- 需求：BR-020、BR-022、BR-024。夹具：F07，实现真实的执行／结算顺序已经记录。
- 步骤：分别在确认前、提交后待核实、转移已发生而结算未最终落定、完成后恢复；若实际顺序为先预扣再转移，也覆盖预扣后窗口。恢复时重复投递已见结果。
- 预期：确认前无操作，待核实按未知规则恢复；成功只结算一次，明确失败只补偿一次；已完成不重放。无法直接保存的窗口用已验证测试钩子覆盖并说明局限，不能假定 UI 请求与扣费是原子事务。
- 证据：各阶段真实状态、钩子／存档和恢复路径、所有者／费用／行动前后、唯一结算关联。未覆盖的必要窗口记阻塞。

<a id="tc-031"></a>
### TC-031 特殊城市与随城资产完整性

- 需求：BR-018、BR-023。夹具：F05，特殊对象支持矩阵已冻结；清点人口、建筑、区域、奇观、巨作／槽位、驻军、占领与忠诚度。
- 步骤：对支持的普通／特有资产组合逐项征取并跨回合检查；对配置不支持的首都／城邦等检查明确拒绝。特殊类别各用独立副本。
- 预期：支持与拒绝均按规则，不将某类技术失败变成未说明的永久禁令；资产保留／转换／损坏及收益有明确映射，无无解释丢失、复制或残留旧控制。赠送城邦通过不能替代主要文明城市测试。
- 证据：完整资产清单及前后映射、合法性／拒绝原因、收益、占领与忠诚度状态；不能仅依赖读取建筑列表的源码存在。

<a id="tc-032"></a>
### TC-032 独立建筑的实际控制与持续收益

- 需求：BR-019、BR-023。夹具：F06，明确建筑真实所属城市／区域、控制方式与规则；若尚无可行机制则本例 BLOCKED。
- 步骤：选择真实敌方建筑为目标，由玩家支付并夺取；核对建筑与关联城市／区域状态；保存读档并推进至少两个收益结算点；检查原控制者及第三方对照资产。
- 预期：按用户选择，实体建筑留在原处、原城仍归对手，收益和使用权转给白绮，旧控制者失去对应经营效果；建筑关联与配置一致。只夺整城、给己城复制建筑、临时 UI 标识或一次性战利品均不满足本例。P2 普通粮仓具体核对原城 -1 粮食／-2 住房、接收城市 +1 粮食／+2 住房，并覆盖受损暂停、修复恢复、源城／接收城易手及经营权上限。
- 证据：经核实的实际读取方法、资产身份和关联、前后控制／收益与费用、读档后持续性、第三方不受影响。不得发明 `ControllerID` 等接口作证据。

<a id="tc-033"></a>
### TC-033 独立区域／地块设施的控制

- 需求：BR-019、BR-023。夹具：F06，对区域与改良分别冻结支持范围、城市关联及地块控制规则。
- 步骤：分别执行支持类别的玩家夺取；检查关联城市、区域／地块所有权或使用控制、通行与收益；跨收益结算点并保存读档。
- 预期：每类的真实效果符合所声明控制方式，持续收益不重复、不留双重有效所有者；不暗中改变非目标城市或第三方资产。仅掠夺收入不算设施夺取，区域成功不自动证明改良成功，反之亦然。
- 证据：各类别单独的资产／地块前后映射、控制与收益、费用、恢复和第三方对照。未支持子类说明边界，不能据此将全部独立设施需求判完成。

<a id="tc-034"></a>
### TC-034 合格目标不会诱发后台征取或外交

- 需求：BR-014、BR-016。夹具：F04／F05，军队、余额和目标均符合征取条件，玩家不确认；另备和平但可能有利扩张的场景。
- 步骤：后台运行多个规划点；随后玩家仅对一个指定目标确认一次；观察其他军队及对外关系。
- 预期：确认前征取请求为零，后台不宣战／议和、不移动军队；确认后只执行该请求许可的动作与代价，其他单位命令和目标不被改变。
- 证据：后台与玩家来源分别计数、外交状态、目标和关联号、余额／行动与军队订单。

## 兼容、长局与证据质量

<a id="tc-035"></a>
### TC-035 原版界面与声明的兼容组合

- 需求：BR-027。夹具：F01，先用原版界面基线；对声称兼容的生产／地图界面模组组合各建独立配置。
- 步骤：打开生产面板、手动改队列、查看区域放置，切换托管；存在其他写入者时跨规划点观察。
- 预期：原版功能可用，无面板错误和队列来回覆盖；冲突按声明策略暂停／交还并说明。只对已测组合报告兼容，不把未测写成兼容通过。
- 证据：模组清单与版本、队列写入来源、界面／脚本日志及冲突恢复记录。

<a id="tc-036"></a>
### TC-036 十城性能与有界工作

- 需求：BR-026、BR-028。夹具：F08，冻结 `B_plan`、`B_turn`、`B_delta`、`N_req`、样本长度和预热长度。
- 步骤：用匹配的十城托管开／关副本测量；记录每次规划与每回合累计耗时、请求数、额外回合耗时；加入无合法城址／候选很多的压力状态。
- 预期：p50／p95／最大值和超预算次数完整报告；达到冻结预算与请求上限，无无限循环、持续刷日志或明显卡死。不同 AI／随机事件的耗时波动单列，不能全算模组耗时。
- 证据：计时方法、原始样本、机器与环境、汇总分位数、超限原因和请求上限检查；不得用 HTTP 延迟代替游戏性能。

<a id="tc-037"></a>
### TC-037 五城二十回合的少操作验收

- 需求：BR-002、BR-025、BR-028。夹具：F08，五城均有正常任务；场景保证有能在窗口内完成的建筑与区域／改良机会，并记录初始队列与成本。
- 步骤：连续二十回合只执行军队、结束回合和范围外必要操作；不手动选生产／区域／建造者任务。逐回合记录队列、任务结果、提示与点击。
- 预期：强制逐项内政点击为零；至少有实际建筑完成、区域建成与建造者改良／修复证据，非五座空城安静待机；新城加入与失败说明符合规则，无阻断性错误。军事待命／科技等提示分项记录，不把游戏所有点击都要求为零。
- 证据：逐回合五城表、真实完成清单、点击分类与录屏／截图、费用／资源／人口记录；若场景不再有任务，解释并重建适当夹具，不能空跑判通过。

<a id="tc-038"></a>
### TC-038 经济压力与脱离模型服务运行

- 需求：BR-015、BR-028。夹具：F08，财政／资源／人口接近策略边界，另有敌方掠夺或贸易变化副本；游戏可正常运行而本地模型服务不可访问。
- 步骤：记录正常收支和边界，运行多轮生产与扩张；使外部收入下降后再规划；期间保持模型服务不可用。
- 预期：自动新增承诺不突破冻结预算，变化后重新评估，避免仍按旧预算连续招募；不得无授权解散军队救财政。解释自然维护费／外部损失，模组无需模型、密钥或网络回复即可正常托管。
- 证据：决策时预算与实际收支分解、请求／队列变化、单位状态、无运行时模型依赖的实现审查与离线行为；不需修改 Steam 或全机网络配置。

<a id="tc-039"></a>
### TC-039 支持版本、存档边界与升级

- 需求：BR-024。夹具：F07，已声明的同版本读档与升级路径，含在途扩张、手动暂停和已结算征取状态。
- 步骤：同版本重复保存读档；对声明支持的旧版存档升级；对不支持版本按声明方式尝试加载并观察提示／安全处理。
- 预期：支持路径无存档损坏、重复任务或费用，手动状态保留；不支持版本不无声套用旧数据发操作，明确报告范围与恢复办法。游戏版本变更后需重新核对关键入口，不能沿用预研通过结论。
- 证据：模组／存档格式版本、升级前后状态、日志与支持矩阵。不能要求未承诺的所有历史版本可用。

<a id="tc-040"></a>
### TC-040 缺失状态、请求记录与证据真实性

- 需求：BR-026。夹具：F07，合法测试钩子可分别模拟所有者／编队／合法性读取缺失及请求未被接受。
- 步骤：各分支触发规划；检查是否停发、是否有有界原因；对一条已发送但引擎未完成的请求查看结果记录；核对记录与独立状态。
- 预期：关键检查未知时跳过，不默认允许；“提交”“接受”“完成”“未知”不混用，不把未变化资产标成成功。记录能关联对象与动作来源，重试有上限，无持续刷屏；无法取证记阻塞。
- 证据：注入范围与方法、原始诊断、实际游戏状态、请求数和原因提示次数；日志字段可读不等于功能通过。
