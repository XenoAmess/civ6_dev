# 测试玩家的结束回合流程

2026-11-04，机器BF-202609141645。来源为本机原版Base/Assets/UI/ActionPanel.lua及WorldInput.lua；游戏源码原件不公开。以[73实机证据](../research/baiqi-p6-native73-builder-queue-progress-evidence-2026-11-04.json)为当前窄样本。

原版ActionPanel的正常结束使用UI.RequestAction(ActionTypes.ACTION_ENDTURN)，没有REASON。带REASON='UserForced'对应Shift+Enter，原版注释标为不支持；它可绕过通常流程，不能作为正常排队移动执行的通过证据。本轮71—73早期所检调用曾被误称为普通结束，历史事实和原件保留，标签在后续证据纠正；不追认其他历史窗口已完成本流程复核。

正常DoEndTurn会根据阻塞与军队待命情况选择下个可操作单位或请求结束。正式结束动作可能先执行已有排队移动而仍留在当前回合；必须读回实际回合、位置、行动和排队目标，不能把ACK当换回合或移动完成。UnitManager.GetQueuedDestination是已验证的UI只读入口，不能因某模型声称“无查询API”而忽略它。

测试代理扮演TEST_PLAYER，可以处理军队、外交与回合；BACKGROUND模组仍不得调军队或外交。需要跳过军队时，只操作新鲜选中的自有军事／支援／宗教战斗单位，并核完整ID、类型、当前玩家、回合、空闲、资格及护送；同回合同单位已尝试的跳过不能重放。不得替AI移动文职、建造、改队列、取消排队路线、清未知回执或补发原移动。

73实际采用了10个有限步骤：6支军队仅跳过、4次DoEndTurn选择，随后4次无REASON正式动作；其中两个动作执行队列而尚未换回合。接口路径仍不是全部物理按钮／剩余军队提醒矩阵通过。测试工具12项边界检查通过，模型369原代码仅7项通过而拒绝；正式游戏动作由负责人审阅后的工具执行。

每个游戏动作前保存唯一尝试凭证，核当前自有进程和真实端点；一个Native写者串行执行，子进程终态后再操作。结果未知时先读回，不靠HTTP重试或重复脚本重放。阶段结束恢复观察器、清理QA临时命名空间、保存现场；模式确认和Steam离线规则仍按[既有流程](../steam-offline-workflow.md)。
