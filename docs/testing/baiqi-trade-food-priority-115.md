# 115：缺粮城的新商路先比口粮

[邢州 213 的实机](baiqi-food114-trade-gap213.md)显示：胶东商路少掉 3 粮时，1.75 的库存挡不住这次人口损失。商人很快续上商路，但原版已经扣了人口。[212 的原版贸易列表和候选收益](baiqi-food114-prevention-audit212.md)说明，距离近和产粮多并不是一回事。

115 只改空闲托管商人新开国内路线的顺序。出发城市净粮不大于 0、库存少于 2，并且有 2 至 16 个路径候选时，读取原版贸易计算的基础、路径和修正三项粮食。三项对所有候选都已知，才优先考虑较多粮的路线；同粮则沿用路径长度、城市 ID。遇到缺值或异常，沿用原排序。商路容量、原版资格、视野、敌军和边界检查仍适用，高粮路线被拒可继续检查安全替代路线。

旧版的针对测试复现了近路压过多粮路线；新排序测试还覆盖了隐藏路径、异常读数、正常粮食库存和容量已满。用 115 的估算函数在 114 实机做只读预验，邢州九个候选的估算都能读出，西安 5 粮、胶东 3 粮。当时的实际容量为 9/9，没有取消或新开路线，也没有改变粮仓库存。

这条改动只改善未来的选择，不会改动活动商路，不能算通过 213 人口损失回归。正式 115 又检查了两个实机存档：216 长沙符合低粮条件，但 9/9 商路全部在跑；153 的旧缺粮档中，原有食物偏好策略先把长沙净粮从 −1 拉到 +5，商路也已 6/6。两处都没有可启动排序的空闲商人。实际通过仍需要一个有空闲商人和商路容量的低粮城市，从自动选择一直观察到原版商路真正生效。
