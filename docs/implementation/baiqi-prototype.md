# 白绮原型：安装、实现与当前验证范围

更新：2026-10-31。当前交付的是可安装的自动内政开发原型，尚未达到[完整需求](../requirements/baiqi-requirements.md)的全部验收条件。有偿夺取的实际转移／收费入口尚未开放，不能把已有结算状态机当成城市或建筑夺取已经实现。

## 安装与运行

在仓库根目录通过 CMD 执行：

```bat
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python tools\build_mod.py --install
```

开发测试需要 `lupa` 执行 Lua 5.3；打包工具只依赖 Python 标准库，玩家运行模组不需要 Python、本地模型或网络服务。默认生成 `dist/Baiqi.zip`，并安装至当前用户文档目录的 `My Games/Sid Meier's Civilization VI/Mods/Baiqi`。自定义文档目录可用 `--mods-dir` 指定。安装器校验清单、UTF-8 与 XML，拒绝覆盖非本工具管理的同名目录或用户改过的已安装文件；不递归删除目录。

在游戏“额外内容”中启用【白绮：为我前驱】，新建单人对局选择白绮。原型暂关联中国文明，引用已安装的中国标志与加载画面，不包含第三方美术文件，也不继承秦始皇领袖能力。前端注册提供标准／迭起兴衰／风云变幻入口，**本机实测目前只进入了风云变幻**，其余规则集尚未验证，不能据此宣称完整兼容。

内政默认开启。面板提供总开关、所选城市／文职接管与所选对象所在地块保护；军队继续由玩家操作。科技、市政、政策、外交和结束回合仍由玩家决定。选中文职后接管可暂停，明确交回后恢复；所有设置由游戏侧保存到存档属性。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| [模组清单](../../mod/Baiqi/Baiqi.modinfo)与 `Config/`、`Data/`、`Text/` | 新领袖、能力、本地化、文明关联及原版图标引用；不覆盖原版脚本。 |
| [BaiqiPolicy.lua](../../mod/Baiqi/Lua/BaiqiPolicy.lua) | 白绮／玩家／回合／所有权门槛，明确文职及动作白名单，未知编队状态拒绝操作。 |
| [BaiqiPlanner.lua](../../mod/Baiqi/Lua/BaiqiPlanner.lua) | 无引擎副作用的选择、招募预算、城址预留筛选与支付状态转换。支付状态转换尚未连接实际夺取。 |
| [BaiqiController.lua](../../mod/Baiqi/Lua/BaiqiController.lua) | 读取真实状态、规划空队列、区域坐标、建造者与移民操作；发出前重检，之后核实队列／单位变化；记录请求来源。 |
| [BaiqiGameplay.lua](../../mod/Baiqi/Lua/BaiqiGameplay.lua) | 接收原版 `EXECUTE_SCRIPT` 路由的设置请求，核对玩家和对象后保存。 |
| [BaiqiPanel.lua](../../mod/Baiqi/UI/BaiqiPanel.lua)与 XML | 附加界面、默认显示与生命周期，退出或热加载时移除本模块事件监听。 |

原型参数在 [BaiqiConfig.lua](../../mod/Baiqi/Lua/BaiqiConfig.lua)，配置标识 `BAIQI_P1`。每 0.35 秒检查一次，每回合最多 64 个请求，每城最多检查 512 个候选；候选失败后本回合不持续重试。财政储备 100，招募后预测净收入至少 2；移民最低人口 4，全帝国最多一个已有／在建／预留移民承诺；建造者目标每两城一个，军队目标每城两个且至少两个。这些都是待平衡的原型选择，没有性能或平衡达标结论。

文职每次只请求一格已探明安全路径，不带攻击修饰；不进入外方领土，不动护送编队。可见敌方威胁会延后操作，不保证躲开未知敌军。区域目前保护已有设施、地貌、可见资源及手动保留地块，不能为区域收益擅自清除这些资产；建城按原版合法条件执行，包括正常开局在林地建立首都。

## 已得到的实机证据与修正

本机 Steam Build `15296837`、游戏 `1.0.12.68 (1023995)`，以白绮进入《风云变幻》单人对局。实际加载页显示正确人物、能力与说明；数据库通过游戏侧外键验证，Gameplay 与附加 UI 脚本载入。当前截图与完整日志留在被忽略的 `.local-model/implementation/`。

已读回开局移民 `65536` 建立位于 `(17,11)` 的西安，移民消耗，城市属于玩家；随后纪念碑哈希 `-2025065568` 出现在真实队列，队列大小为 1。初始勇士 `131073` 在观察窗口仍为 `(17,12)`、移动力 2。首次建城由诊断调用托管执行器触发，所以这个结果只证明执行链路，不能单独证明无需介入的默认流程已通过。

实机暴露并修正了两个生命周期问题：原版 `InGame.lua` 会隐藏新加载的附加 UI，需在视图就绪／回合事件显示；热加载退出还必须移除事件监听。早期现场已有旧回调错误，完整通过结论必须等修正版冷启动回归。

另一个重要发现是生产合法性：未研究制陶术时，粮仓的 `CanProduce(hash,true)` 为 false，而 `CanProduce(hash,false,true)` 为 true；只用后一项或 `CanStartOperation` 不足以判合法。原型已按原版 `ProductionPanel.lua` 组合两种模式，并补真实控制器的逻辑回归，实际队列已改为合法纪念碑。

当前 **26 项软件测试方法通过**：包括实际 Lua 源码加载、军队与护送隔离、非零玩家编号、预算和预留、未知／重复支付状态、真实控制器的生产门槛、打包与安装防覆盖。这里的 API 测试替身不等于游戏引擎，不能记为 26 项游戏功能通过。

## 尚待完成的验收

- 修正版冷启动后的自动首都、正常建筑完成与队列接续；已入队不能算已建成。
- 区域真实建成、建造者移动／次数／修复，以及正常训练后续移民的完整扩张。
- 总开关和局部接管的保存读档、多类型军队与护送实机隔离、五城二十回合和十城性能。
- 玩家确认的有偿城市转移、独立建筑／设施控制、真实费用结算与未知结果恢复。目前不收取夺取费用，也不展示可执行的夺取按钮。

具体用例与判据仍按[验收方案](../testing/baiqi-acceptance-plan.md)执行。源码预研中新增找到作者直接使用的 `CityManager.TransferCity(pCity, iPlayer)` [记录](https://steamcommunity.com/sharedfiles/filedetails/changelog/2141200494)，[API 作者索引](https://sukritact.github.io/Civilization-VI-Modding-Knowledge-Base/CityManager)也标注其为游戏脚本侧方法；这些支持下一步验证，不证明本原型已完成转移。调试连接协议参考 [civ6-mcp 作者源码](https://github.com/lmwilki/civ6-mcp/blob/main/src/civ_mcp/tuner_client.py)，连接与诊断脚本只在本机，不成为玩家依赖。
