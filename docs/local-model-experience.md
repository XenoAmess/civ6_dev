## 可复用的历史经验

- 当前源码、实际 API、生产者/消费者和精确诊断比仅给文件路径更有用；完整上下文不代表模型已自主实现所有输入文件。
- 模型曾能提出可用的窄方法或局部合同修改；完整 ABI、跨文件恢复图仍可能需要负责人接管。成功与失败只能支持对应任务条件下的分工判断。
- 先让模型实现真实待办，审阅期间继续派其他独立任务；不为刷数量重发已完成实现。
- 实际 `request.json` 决定参数是否发送；请求 thinking 开关不证明服务实际内部模式。不能根据耗时推断缓存命中。
- 半截 SSE、输出 length、接口缺 tool parser、候选逻辑错误分别记录；不把传输错误计作模型推理能力上限。

这些均来自上述 CK3 固定版本资料，不是本项目已取得的 Civ6 运行、性能或玩法验证。

## 2026-10-31 白绮命名与自动扩张规格

用户确定【白绮】与【代我执行】，要求自动生产、自动建造、自动扩张，保留军队指挥权。本轮使用当前本地原版调用点，向模型并行派发扩张状态分析与分工规格两项真实待办；2 次实际 HTTP、客户端峰值 2、无自动重试，均为 HTTP 200 和完整 stop/SSE/JSON。具体回执及原版文件指纹见[扩张证据](research/baiqi-expansion-evidence-2026-10-31.json)。

规格候选的简短能力说明与分工结构部分采用；名字、自动化范围、军队生产与行动的区别、护送编队跳过规则已由用户及负责人提供，不能算模型独立发现。负责人把模型写成固定禁令的科技／外交事项改为尚未纳入本轮自动化范围。

扩张候选的建议地点与合法性区分、到达重检、编队隔离和恢复场景部分采用。模型同时建议查询未给出来源的远程建城目标接口和 `OnUnitMoveComplete` 回调，并把训练移民的人口／预算条件混放到建城阶段；这些内容拒绝采用，正式规格保留接口待验证，并正确区分生产成本与到达后的建城条件。

负责人首次准备材料时，因原版 `UnitFlagManager.lua` 含非 UTF-8 字节而在 HTTP 前失败；随后以 Latin-1 保留字节映射核读 ASCII 调用点，原字节 SHA-256 保持。该准备错误不计模型失败、HTTP 请求或服务重试。本轮仍只更新设计与源码依据，没有执行自动移动、建城或军队隔离实机试验。

## 2026-10-31 为我前驱与有偿夺取

用户把能力改名为【为我前驱】，并新增军队满足条件、支付代价夺取他人城市、建筑等的要求。本轮并行派发玩法草案与技术边界两项真实待办：2 次实际 HTTP、客户端峰值 2、无自动重试，均为 HTTP 200、完整 stop/SSE/JSON，缓存数据未报告。回执与原版文件指纹见[夺取预研证据](research/baiqi-requisition-evidence-2026-10-31.json)。先前阶段的标题与回执保留当时能力名，当前规格使用新名。

玩法候选的玩家主动触发、费用展示和单独研究设施归属部分采用。负责人拒绝模型擅加的首都／城邦／奇观永久排除和含糊的冲突状态，补充明确的战时邻接、城防与行动成本草案；所有具体条件和数值仍待确定，不能当作用户已认可的固定参数。

技术候选的城邦吸收 modifier 链和状态核对试验部分采用。拒绝把 `OwnerCity:GetBuildings()` 当成所有建筑都能随城保留的证明、把新增 `EffectType` 当作已有引擎实现、把未检索到接口当作全局不存在，以及失败后让玩家破产的无依据建议。负责人保留独立建筑／设施夺取需求，区分赠送与战时接管，补齐未知结果不重放、费用不重复结算及读档恢复的验收。

本轮没有运行城市转移、设施转移或费用扣除。源码中找到特定城邦效果，只支持研究对应路径；不能外推为任意敌方主城或单独建筑已经可以接管。
