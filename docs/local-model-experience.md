## 可复用的历史经验

- 当前源码、实际 API、生产者/消费者和精确诊断比仅给文件路径更有用；完整上下文不代表模型已自主实现所有输入文件。
- 模型曾能提出可用的窄方法或局部合同修改；完整 ABI、跨文件恢复图仍可能需要负责人接管。成功与失败只能支持对应任务条件下的分工判断。
- 先让模型实现真实待办，审阅期间继续派其他独立任务；不为刷数量重发已完成实现。
- 实际 `request.json` 决定参数是否发送；请求 thinking 开关不证明服务实际内部模式。不能根据耗时推断缓存命中。
- 半截 SSE、输出 length、接口缺 tool parser、候选逻辑错误分别记录；不把传输错误计作模型推理能力上限。

## 2026-10-31 首个可安装自动内政原型

用户授权开始制作后，先并行派发 12 项独立真实任务：策略门槛、预算、生产选择、城址、建造者、移民、支付日志、面板、领袖注册、两个引擎适配分析与夺取路径分析；随后并行派发控制器审阅、测试与安装工具，最后把截断审阅缩为最多六条问题。机器仍为 `BF-202609141645`。

共 **16 次实际 HTTP、实际在途峰值 12、无自动重试**；14 次完整 stop/SSE/JSON，面板与首轮控制器审阅两次 length，均拒绝采用、不拼接。未知缓存与服务端推理并发保持 null。完整逐项回执、输入请求哈希、源码指纹与采用说明见[原型证据](research/baiqi-prototype-evidence-2026-10-31.json)。这些数字不能当成实现的模块数或游戏验收通过数。

采用了部分白名单／预算／生产／预留的结构、领袖注册字段思路，以及测试场景和安装状态结构；负责人做完整集成与验证。关键拒绝项包括：写死玩家 0、用地块编号模 1000 计算邻接、将快照 ID 当原生单位对象、错误的预留自引用、未知结算状态无法恢复、复制产品代码进测试、非法 Lua 字面量、打开但不读取文件来“验证 UTF-8”、非规范路径判断、重复压缩清单和根据不可信旧安装状态删除文件。

窄审阅虽然传输完整，六条结论多数误解 Lua 短路求值或忽略已有身份检查；不因为输出完整就采用，也不接受将缺失确认当默认 false 的建议。负责人继续依据真实消费者与实机状态修正。

实机暴露负责人准备和集成的缺口：原版 `InGame.lua` 把附加 UI 以隐藏方式载入，单有更新回调不会自动显示；热加载必须移除事件回调；首次过度保守的林地建城限制也阻止了开局。生产候选还漏掉原版 `CanProduce(hash,true)` 过滤，只用另一种模式会把未解锁粮仓当成候选，实际请求不入队。上述问题均在源码和逻辑测试中修正，修正后的默认流程仍需冷启动回归；不能把这些负责人集成错误写成模型已自行解决。

最终软件测试 **26 项方法通过**，其中原调用器 8 项、新增 Lua 模块／真实控制器替身／打包安装 18 项。实际引擎已载入白绮，诊断触发建城后读回西安、移民消耗，修正后读回合法纪念碑队列；初始勇士在受控窗口未被移动。未完成建筑、区域、后续移民、读档、性能或夺取的完整实机验收，完整游戏用例通过数为 0。安装与实机范围见[原型说明](implementation/baiqi-prototype.md)和[运行记录](testing/results/2026-10-31-p1-smoke.md)。

## 2026-10-31 城市与原位粮仓经营权实现

用户明确选择建筑留在原地、收益与使用权转给白绮。本阶段先派真实未完成的报价、结算日志和故障测试，再做窄报价纠错、手动界面／经营权机制候选和针对当前代码的审阅。共 **9 次实际 HTTP，实际在途峰值 3，8 次完整 stop/SSE/JSON、1 次 length，无自动重试**。实现阶段累计 25 次请求、历史峰值 12；本阶段峰值仍为 3，不将累计数当并发。缓存和服务端推理数保持 null。逐项输入指纹、回执与采用范围见 [P2 证据](research/baiqi-p2-evidence-2026-10-31.json)。机器仍为 `BF-202609141645`。

报价候选先后两次漏掉明确合同：虚构单位领域／地块接口、错误兵种枚举、混合城市与外防生命、拒绝没有城墙的目标、引用控制器私有方法，或用总托管开关禁用玩家手动征取。负责人接管；没有将改写完的报价重发模型复述。日志候选错误排除 UNKNOWN 冲突、永久锁住已完成操作；测试候选只有注释中的断言，未采纳为可执行测试。

手动界面仅保留弹窗／请求组织思路，拒绝读取迷雾目标、虚构 UI 完成事件和先打印 committed 的做法。经营权方案没有负向原城效果，错误地让接收城市读取源城属性，住房值错误，还虚构 modifier 实例标识和卸载 API，整体拒绝。负责人采用原生建筑／市中心 modifier 和地块属性门控，实测粮食／住房实际变化后再接入费用。完整审阅 length 输出原件保留，未拼接或采用。

后两项窄审阅指出的孤立效果与陈旧 pending 情况部分采用：加入存档结构／上限校验、首次载入清理和下一回合明确缺回执状态；不超时退款、不自动重放。拒绝重新收费恢复受损建筑、静默截断经营权收益，以及“confirming 未清除”的误报。受损经营权按原记录暂停，修复后免费恢复。

负责人实机修正包括：新增清单文件须重载内容；游戏逻辑层是 `Player:IsHuman`、`Unit:GetType`、城市 `GetDistricts():GetDistrict`，与 UI 接口不一致；原型现用实际能力分支和游戏侧 API 替身。原合同错误写成普通 `PopupDialog:new`，原生对局应使用 `PopupDialogInGame:new`，负责人依据原版 UnitPanel 修正。读档中已消耗移民仍可能有无效坐标，需等视图就绪并跳过无效对象。这些是集成／合同错误，不宣称模型已解决。

本轮 **44 个软件测试方法通过**。实机已从面板取消、确认征取粮仓，观察原建筑留在敌城、原城 -1 粮食／-2 住房、白绮接收城市 +1 粮食／+2 住房、150 金币／行动结算；三次重复、完成态读档和下一回合没有叠加。随后整城原位转移、300 金币结算和新城自动生产入队，旧经营权结束。其他资产与完整 40 项游戏用例仍未验收，详细限制见[实测报告](testing/results/2026-10-31-p2-requisition.md)。
