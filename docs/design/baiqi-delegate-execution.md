# 白绮与为我前驱设计规格

领袖名称确定为【白绮】，领袖能力确定为【为我前驱】。核心体验是自动生产、自动建造、自动扩张，玩家亲自指挥军队，并可在满足条件、支付代价时夺取他人的城市、建筑等。内政默认自动运行，军队主动能力由玩家决定使用；当前处于设计与源码预研阶段。

行为要求与来源见[需求清单](../requirements/baiqi-requirements.md)，正式测试方法见[验收方案](../testing/baiqi-acceptance-plan.md)和[40 项用例](../testing/baiqi-test-cases.md)。本页的流程与原型目标不代表游戏测试已通过。

## 能力说明

> **为我前驱**：自动安排帝国的生产、建设与和平扩张。根据当前需求招募单位、经营城市，并派遣移民建立新城。满足条件时，你可命令军队付出代价，夺取他人的城市、建筑或其他设施。军队的行动与作战由你亲自指挥。

生产、建设与扩张按原版规则支付各自的产能、人口、战略资源等成本。有偿夺取是新增的能力分项，详细触发条件、具体费用与设施归属处理见[专项设计](baiqi-requisition.md)，尚未实机验证。额外通用战斗数值加成、所属文明与头像尚未确定。

## 自动化与玩家分工

| 范围 | 为我前驱负责 | 玩家负责 |
| --- | --- | --- |
| 自动生产 | 城市建筑、项目、建造者、移民，以及受预算和需求约束的军队招募与补充 | 随时指定生产内容和兵种，手动队列优先 |
| 自动建造 | 区域选址与建设、建筑升级链、掠夺后的修复、建造者移动及合法改良 | 可暂停托管、保留地块或接管具体城市和文职单位 |
| 自动扩张 | 安排移民、评估已探明城址、选择可行路线、到达后建城；新城自动接管 | 军事侦察和战争扩张；对占领城市决定保留或夷平 |
| 军队指挥 | 训练完成后把新部队交给玩家 | 移动、攻击、驻防、休息、升级、编队、护送、解散，以及海空军行动 |
| 有偿夺取 | 只执行玩家确认的目标与代价；成功取得的城市接入内政托管 | 指定军队、目标和发动时机，决定是否支付；不能由后台自动触发 |
| 对外关系 | 当前不安排自动外交 | 宣战、议和及条约决定 |
| 其他内政 | 科技、市政和政策尚未纳入本轮自动化 | 继续保留原操作，后续可独立研究 |

“自动生产军队”与“自动指挥军队”是两个动作范围。招募出的单位等待玩家下令，生产控制器不能给其附带行军、攻击或自动探索指令。支援单位与斥候也属于玩家的军事控制范围。

默认无需逐城确认。界面只需提供总开关和城市／文职单位的手动接管入口，具体角色与优先级由局势推导，不增加多套资源和逐城配置菜单。回合结束仍由玩家操作。

## 一局中的默认流程

1. 选择白绮进入游戏后，开局移民纳入自动扩张，在当前已探明范围内评估首都位置并建城；这一行为需要在原型中验证。
2. 城市优先解决修复、粮食、住房、财政和生产能力，随后补充军事与科技设施。玩家指定的建设先完成，再由托管补充空队列。
3. 财政、人口、城市承载力和安全城址允许时，系统安排移民。已有移民或在途扩张任务会占用扩张名额，避免不断重复训练。
4. 移民在已探明且可安全通行的路线移动，到达后重新检查建城条件，合法时建立新城并接入生产与建设托管。
5. 系统根据资源、维护费、现有兵力及玩家生产安排补充军队。所有军事行动继续等待玩家指挥。
6. 玩家攻下城市并选择保留后，城市加入自动建设，优先恢复关键设施；战场单位保持玩家原有命令。
7. 玩家也可对满足条件的目标使用有偿夺取动作；费用与执行结果核实后，新取得的城市接入托管。自动内政不会替玩家选择或发动这一动作。

扩张没有安全地点或路线时延后，并在必要时提供一次说明。系统依据可见情报避险，不能调用军队清路、自动护送或自动宣战，也不能为扩张绕过战争、边境或地形限制。

## 军队指挥权的实现边界

生产规划器只提交城市生产请求。文职执行器采用明确的单位类型与操作白名单，分别验证移民、建造者和后续确认的商路行为；不能仅凭“非战斗单位”就接管间谍、伟人或其他特殊单位。

后台每次操作都重新检查当前玩家、白绮身份、回合、单位所有权、单位类型、手动接管状态与编队状态。军队、支援单位及斥候不能进入后台自动动作队列。玩家主动确认的有偿夺取走独立军队操作路径，只处理该次指定的目标和代价。

原版 `UnitPanel.lua:2239` 使用 `GetFormationUnitCount() > 1` 标记编队状态。凡文职单位处于编队中，自动执行器先跳过，不下移动命令、不主动解除编队。这样避免移动移民时连带调动其军事护卫。无法读取编队状态时也保持该单位不动，交由玩家操作。`GetMilitaryFormation()` 表示军团／集团军等形态，不能用来替代这个检查。

玩家手动移动或接管文职单位后，自动任务暂停；明确交回托管后才重新规划。读档、单位被俘或失去、城市转手后先核对真实状态，不重放旧动作。

| 同文件 `OnUnitActionClicked_FoundCity:2621` | 在确认后或无需确认时提交 `RequestOperation(...FOUND_CITY)` | 需验证自动调用下实际建城、移民消耗及新城接管；涉及地貌变更时保留明确保护规则 |
| `Base/Assets/UI/UnitFlagManager.lua:297` | 对 `MOVE_TO` 做合法性检查后提交移动请求 | 原回调还包含先尝试远程攻击的分支，文职执行器不能照搬整个回调 |
| `Base/Assets/UI/Panels/UnitPanel.lua:2239` | `GetFormationUnitCount() > 1` 用于显示编队状态 | 需实测移民与护卫绑定、多回合路径及读档后的行为，确认军队不被间接移动 |

扩张规划按“需要扩张 → 预留城址与移民名额 → 正常训练 → 选择路径 → 到达重检 → 发出建城请求 → 核实新城 → 接入托管”推进。失败后保留原因并重新评估，不重复发出未经读回的建城请求。

城市买地可以作为带储备金和单回合预算的扩展功能；具体买地操作尚未纳入本次核查。它不能取代移民正常建城，也不能在实现前计为已支持的自动扩张。

## 扩张与生产的经济约束

- 训练移民前检查人口和正常生产条件，并计入已有移民、在建移民、已预留城址与扩张任务。
- 招募军队前检查资源、维护费、财政储备和实际兵力需求；已有足够军队时安排建设或后勤项目，避免无限出兵。
- 移民到达后检查当前位置建城条件。训练移民的产能与人口成本发生在生产阶段，不能混作建城指令到达时的扣费条件。
- 军队与移民争用产能时，结合城市基本需求和可见威胁调整；玩家指定的生产安排始终优先。
- 有效城址、财力或道路条件不足时，继续经营现有城市，不为维持扩张频率制造无效任务。

## 原型验收

1. **身份与默认接管。** 选人界面显示【白绮】与【为我前驱】；仅该领袖的本地玩家城市和允许的文职单位进入自动化。
2. **城市生产与建设。** 延续五城连续二十回合的目标，验证自动生产、区域选址、修复、正常产能与手动队列优先；目标尚未达成。
3. **和平扩张。** 在受控测试地图准备开局移民与另一名移民，分别验证自动建立首都、第二城的选址、正常移动、到达重检、真实建城及接管。另行验证从正常城市生产移民开始的完整扩张过程。
4. **军队操作隔离。** 建立移民与军队护送编队，自动执行器跳过该移民；后台自动化发出的军队命令为零，军队坐标、行动力与订单不会被文职自动化连带改变。回合刷新、敌方行动与玩家原有多回合命令造成的变化单独归因，不能要求跨回合状态绝对不变。新训练军队交给玩家指挥。玩家明确确认的有偿夺取，只能提交对应军队的一次指定动作，并核验其他军队订单不受影响。
5. **人工接管与恢复。** 玩家指定城市生产、移动移民或关闭托管后，自动化停止争抢；重新启用时依当前状态规划。保存读档、单位失去和城市转手均需覆盖。
6. **无路或无城址。** 可见敌军、封闭边界、失效地点和竞争城址导致延后或重规划；不自动宣战，不借用玩家军队解决，不反复弹窗或无限刷请求。
7. **经济限制。** 不因持续生产移民抽空城市人口，不因持续招募军队耗尽资源和财政；规则集、游戏速度及单位成本通过实际游戏状态计算。

先完成生产与建设，再闭合文职改良和自动扩张；有偿夺取单独验证归属变化、代价与玩家操作，再合并全流程。各模块的完成范围单独记录；找到调用入口或完成部分模块不能记为【为我前驱】已经全功能可玩。
